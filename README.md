# Scout Website — HTML5 / CSS3 / JavaScript (single deployable package)

This is a full conversion of the original React + Next.js "Scout-Website"
project (Public Website + Admin Panel) into **plain HTML5, CSS3 and
vanilla JavaScript** — no React, no JSX, no build step, no framework.
It now ships as **one folder you can deploy as a single app**, served
by a tiny zero-dependency Node.js static server.

## Folder structure

```
server.js        ← the whole "backend": a zero-dependency static file server
package.json      "npm start" entry point
public/           the public website  -> served at  /
  index.html
  css/style.css
  js/data.js
  js/app.js
admin/            the admin panel     -> served at  /admin/
  index.html
  css/admin.css
  js/data.js
  js/app.js
  js/pages.js
  js/pages2.js
```

## Run it locally

You only need Node.js installed (no `npm install` required — the
server uses only Node's built-in `http`/`fs` modules):

```bash
node server.js
# or
npm start
```

Then open:
- Public website: **http://localhost:3000/**
- Admin panel: **http://localhost:3000/admin/**

Change the port with `PORT=8080 node server.js` if 3000 is taken.

## Deploying it

Because it's a single Node.js process with no dependencies to install,
it works on essentially any Node host:

- **Render / Railway / Fly.io / Heroku** — push this folder as-is.
  Build command: *(none needed)*. Start command: `node server.js`
  (or just `npm start`). These platforms set `PORT` automatically —
  `server.js` already reads `process.env.PORT`.
- **A plain VPS** — upload the folder, then run `node server.js`
  (ideally behind `pm2` or a `systemd` service so it restarts
  automatically), and put Nginx/Caddy in front of it for HTTPS.
- **Docker** — a minimal `Dockerfile` would just be:
  ```dockerfile
  FROM node:20-alpine
  WORKDIR /app
  COPY . .
  EXPOSE 3000
  CMD ["node", "server.js"]
  ```
- **Static-only hosts (Netlify/Vercel/GitHub Pages/S3)** — since there's
  no server-side logic beyond serving files, you can also skip
  `server.js` entirely and just upload the `public/` folder as your
  site root and the `admin/` folder as a `/admin` subfolder, if your
  host supports that layout.

## Admin panel login — Firebase Authentication

The admin panel's login is now backed by **real Firebase
Authentication** (email/password), with roles (Super Admin / Leader /
Editor) stored in **Firestore** so they stay in sync across every
browser and device. There's no hardcoded demo password or access key
anymore.

Before the admin panel will work, you need to:
1. Create a Firebase project and paste its config into
   `admin/js/firebase-config.js`.
2. Enable the Email/Password sign-in provider and create a Firestore
   database.
3. Create the first Super Admin (one Firebase Auth user + one
   matching Firestore `admins` document).

Full step-by-step instructions (with the exact Firestore fields and
recommended security rules) are in **[`admin/FIREBASE-SETUP.md`](admin/FIREBASE-SETUP.md)**.

The rest of the admin panel (members, events, notices, etc.) is still
in-memory demo data, same as before — only login/roles are now real.


## What changed vs. the original React project

- All `.jsx` components (React + Tailwind + lucide-react) were rewritten
  as plain HTML generated by small JavaScript template functions.
- All state (`useState`) was replaced with plain JS variables/objects
  and manual re-render calls.
- Routing (`setPage`) was replaced with a simple hash-router (public
  site) / in-memory page switch (admin panel).
- Styling: the original design tokens (CSS custom properties, fonts,
  `.card`, `.btn-primary`, `.patch`, etc.) were copied 1:1 into plain
  `.css` files. Layout/spacing utility classes (`flex`, `grid`,
  `gap-4`, `md:grid-cols-3`, …) are provided by the Tailwind **Play
  CDN** script tag, loaded directly in the browser.
- Icons: `lucide-react` was replaced with the plain `lucide` UMD
  bundle (`unpkg.com/lucide`) + `data-lucide="icon-name"` attributes.
- The bilingual (Bengali/English) dictionary, dark mode, and all sample
  content (news, events, leadership, badges, members, certificates,
  audit log, analytics charts, etc.) were preserved exactly.
- Dark mode and language preference are saved to `localStorage`
  (`sc_dark`, `sc_lang`) on both sites, same as the original.
